# runs —— 每次任务的完整存档

每次任务一个文件夹：`YYYYMMDD_NNN/`

一个任务文件夹从建出来到交付，会陆续长出下面这些文件。
**看第三列就知道能不能动它**：写手只有一个，别人（包括 AI）都不许手改。

| 文件 | 作用 | 谁写 | 性质 |
|------|------|------|------|
| `source/` | 原图的**副本**（`inbox/` 里的原件不动）。识别、归档都从这里的副本走 | `tools\建任务.py` 复制进来；归档时由脚本移走 | 证据 |
| `source/names.json` | **图片台账**：图片编号 ↔ 原文件名 ↔ 真实 sha256 ↔ 字节数 | `tools\建任务.py` | **权威**（编号与指纹以它为准） |
| `raw.json` | **识别原文**：图上到底写了什么（含 `raw_value` 原文与 `value` 换算值、`uncertain` 看不清清单） | **只由 `tools\提交识别.py` 写** | **权威**（证据层，写完不改） |
| `sample.json` | 样板确认记录：哪张图做的样板、什么时候确认的、落成了哪份契约 | `tools\注册表型.py` | **权威**（阶段判定靠它） |
| `样板.xlsx` | 给人看的样板表（5 个页签，第 5 页签请人写确认意见） | `tools\生成样板.py` | 派生（可重出） |
| `样板_契约草案.json` | 从样板图推断出来的契约草案，是 `注册表型.py` 的输入 | `tools\生成样板.py` | 派生（可重出） |
| `issues.json` | **问题账本**：今天需要人判断什么、每条问题影响了哪些行 | `validate_export.py`（`--init-issues` 只刷新它，不生成 Excel） | 权威账本（重跑会整份重写，但人工决定会回填） |
| `decisions.json` | **人的决定**（问题决定 + 归档决定） | `tools\导入审核.py`（从 `task_review.xlsx` 导入，合并绝不覆盖） | **唯一权威** |
| `task_review.xlsx` | 给人审核用的表：`审核总览` / `问题清单` / `待审核数据` / `文件归档清单` | `validate_export.py` | **派生**——每次重跑整表重写 |
| `final.xlsx` | 最终业务数据（宽表，给人看）：`明细数据` + 事实表 | `validate_export.py` | 派生（每次重跑重出） |
| `facts.jsonl` | 机器可读长表：一行一条事实（哪个对象、哪个计量项、多少、单位、原图原文、来源行号） | `tools\导出长表.py` | 派生（每次重跑重出） |
| `archive_plan.json` | 归档计划与实际结果：改什么名、放哪个日期目录、移没移成 | `validate_export.py` | 权威记录（归档结果的唯一出处） |

## 三句话记住谁说了算

1. **识别原文看 `raw.json`**，它只由 `tools\提交识别.py` 写——**AI 不手写、不手改**。
2. **人的决定看 `decisions.json`**，它由 `tools\导入审核.py` 从审核表导入——
   `task_review.xlsx` 是它的打印稿，**重跑会整表重写**，所以你填完必须先导入。
3. **`issues.json` / `final.xlsx` / `task_review.xlsx` / `archive_plan.json` / `facts.jsonl`
   都是"跑出来的"**，删掉重跑就能再生成；`source/`、`source/names.json`、`raw.json`、
   `sample.json`、`decisions.json` 则是**记录**，丢了补不回来。

> **新脚本写的东西都在上面这张表里**，不额外造文件：`导入审核.py` 只写 `decisions.json`，
> `导出长表.py` 只写 `facts.jsonl`，`收尾报告.py` 什么都不写（它只读）。
> `收尾报告.py` 还会检查"审核表填了但没导入"这种坑并提醒你（见 `使用说明.md` 常见问题 Q5）。

## 老任务文件夹可能少了 `source/names.json`

`source/names.json`（图片台账）是**新版流程**才有的，由 `tools\建任务.py` 建任务时写下。
早期（V1.x）手工建出来的任务文件夹里没有它——`tools\提交识别.py` 打开这种任务时会直接拒绝：

```
[错误] 这个任务没有 source/names.json 台账。
       台账由 tools/建任务.py 生成 —— 请用它建任务，不要手工造任务目录。
```

遇到这种历史任务：**不要去手工补台账**（补错了图片编号就全乱），
先跑 `python validate_export.py runs/<任务号> --status` 看它停在哪一步，
再用它自己的数据进行只读操作（`--status`、重跑落账）。要接着识别就往新任务里加图。

## 现有的两个 run 是回归测试样本，不是真实业务数据

`20260910_001`、`20260910_002` 是用假数据造的**回归测试用例**（图片内容是 `fake-photo-1` 这类占位文字），
用来验证 `validate_export.py` 的四类场景：合计超 100%、字迹看不清、必填缺失、同一张图重复提交。

- 不要把它们的数字当业务数据用；
- 真实任务从 `20260911_001` 这类日期往后接着编，不要覆盖这两个编号。
