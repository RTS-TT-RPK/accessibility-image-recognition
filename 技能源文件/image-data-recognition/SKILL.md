# 表格图片转录工作流（图像数据识别转化）

把**任意表格图片**——手机拍的纸质单据、电脑截图、扫描件，印刷体或手写体，任意行业——
变成**可信的结构化数据**。

**三步走：做样板 → 批量转录 → 一次性复核。**

> **模型负责看和写，脚本负责当裁判，人只在两个点出现一次。**

---

## 模型怎么选（本技能不绑定任何模型）

**任何有多模态能力的模型都可以用。** 不挑牌子、不挑厂商、不需要本地部署。

因为模型与流程之间只有一个接口：**`raw.json`**。

```
模型：看图 → 按格式写出 raw.json
脚本：读 raw.json → 确定性校验 → 问题账本 → Excel → 归档
人  ：确认样板 + 复核问题
```

所以**换模型不会破坏任何东西**：
- 历史数据不受影响（`raw.json` 格式不变）；
- 已填的人工决定不受影响（决定按 `issue_id` 存，与模型无关）；
- 换模型不需要改任何脚本、任何契约。

### 对模型的要求只有三条

1. **能看图**：照片/截图，含手写体；
2. **能按指定 JSON 结构输出**；
3. **能如实说"看不清"**，而不是硬猜一个值。

### 怎么判断一个模型够不够用

**用样板试，不要用一百张图试。**

做样板时就盯着看：**该进 `uncertain` 的地方，它是不是硬填了个值？**
- 样板里到处是"看着像就填"的痕迹 → **换模型**；
- 样板干净、看不清的都老实标了 → 这个模型能用。

样板阶段就是模型的试金石，**几分钟就能判断，不用等批量跑完**。

### 两条实操建议

- **同一批图用同一个模型。** 不同模型对"约 90%"这类模糊值的处理、
  列名写法、分行习惯都不一样，混用会让批量一致性变差。
- **换了模型，最好重做一次样板。** 成本是一张图，收益是整批的稳定。

## 第 0 步：先找到工作区（每次都要做）

技能文件本身只是"说明书"，真正的脚本和数据在**工作区**里。本技能可以在 Codex、DSH、
ZCode、Cursor、Claude、OpenCode 等任何读取 SKILL.md 的工具里运行，不要假设工作区在哪。

1. 读本技能目录下的 `workspace.txt`，里面写着一行工作区绝对路径；
2. 该路径存在 → 它就是本次的工作区，继续下一步；
3. `workspace.txt` 不存在、或里面写的路径已经不存在 → **不要猜、不要新建一个空工作区**，按顺序尝试：
   - 在当前打开的项目目录里找 `validate_export.py`（找到就是用这个目录）；
   - 在用户桌面上找名字含「图像识别长期工程」的文件夹；
   - 都找不到 → 直接问用户："工作区文件夹现在放在哪个路径？" 拿到答复后把该路径写回 `workspace.txt`。
4. **检查工作区骨架**：`inbox`/`runs`/`archive`/`golden`/`pending` 缺哪个就跑
   `python tools/初始化工作区.py` 补齐（只建目录和说明，**不删、不覆盖、不动已有数据**）；
   万一连这个脚本也没有，手动建出来并**在汇报里说明**。
5. **检查运行环境**：跑 `python tools/环境自检.py`（退出码 0 = 可以干活）。
   缺 `openpyxl` 优先离线装：`python -m pip install --no-index --find-links "vendor/wheels" openpyxl`；
   连 `python` 都没有 → **先问用户**能否自动装，不同意就给官网链接与
   "务必勾选 Add python.exe to PATH"的提示。完整步骤见根目录 `AI自安装说明.md`。
6. 确认工作区后，先读工作区的 `AGENTS.md`（行为手册）与 `使用说明.md`，再动手。

> **编码提醒（Windows 换电脑必踩）**：工作区所有文本文件是 UTF-8。
> 读文件**优先用 read 工具**；Windows PowerShell 5.1 下必须显式写 `-Encoding UTF8`，
> 否则中文路径会变乱码（`图像识别长期工程` → `鍥惧儚璇嗗埆闀挎湡宸ョ▼`）。
> Python 读 `workspace.txt` 要用 `encoding="utf-8-sig"`。

## 铁律（任何时候都不许破）

1. **不猜**：看不清就记 `uncertain`。日期认不出来就标"日期待确认"，**绝不默认成今天**。
2. **不造数**：表上空白就留白，绝不自动补一个"应该差不多"的数。
3. **不覆盖**：归档只用裁判脚本（撞名自动加序号）；不删 `inbox/`、`pending/` 里未处理的图；
   不改 `golden/` 历史条目。
4. **不改裁判**：`validate_export.py` 是唯一裁判，改动必须由人拍板，
   **改完必须跑 `python tools/回归测试.py` 且全绿**。
5. **不静默**：任何"我改了 / 跳过了 / 没看懂"都必须说清。
6. **批量阶段不打扰人**：疑点记账，留到最后一次性复核。

# 标准流程（三阶段）

## 阶段一：立样板（1 张图，人确认一次）

**为什么要有这一步**：直接问用户"这张表有哪些列、一行代表什么"，
对车间员工太抽象；**做出来给他看，他一眼就知道对不对。**

1. **收图**：原图复制进 `runs/YYYYMMDD_NNN/source/`，逐张算 sha256（识别重复提交）。
2. **挑样板图**：挑一张**有代表性**的——**不要挑最清楚的**，
   要挑最能代表这批图真实难度的（有手写、有涂改、字迹一般的那张）。
   > 如果这批图明显有**两种以上版式**，就做两个样板，别硬凑成一个。
3. **只识别这一张**，写进 `raw.json`（`images` 里先只放这一张）。
4. **生成样板**：

   ```
   python tools/生成样板.py runs/YYYYMMDD_NNN
   ```

   产出两个文件：
   - `样板.xlsx` —— **给人看**：第 1 页"我打算这样录"、第 2 页"这张图读出来的内容"、
     第 4 页"看不清的地方"、第 5 页"请在这里确认"（可打印签字）；
   - `样板_契约草案.json` —— **给 AI 用**：从这张样板自动推断出的版式契约草案。

5. **把 `样板.xlsx` 交给用户**，请他在第 5 页写确认意见。
   要问的就那几件事：这个录法对不对、一行代表什么、列名行不行、哪些必填、
   有没有合计、哪些词是一回事、看不清的格子到底是什么。
6. **用户确认无误后**，把草案整理成 `schemas/<表型名>_v1.json`（格式见 `schemas/README.md`）。
   用户提了修改 → 改草案、必要时重出一版样板再确认，**可以来回几次，数据不会丢**。
7. **记下样板已确认**，写 `runs/YYYYMMDD_NNN/sample.json`：

   ```json
   {"sample_image_id": "IMG_0001", "confirmed": true,
    "confirmed_at": "2026-09-14 10:00:00", "schema": "来料分析_v1",
    "notes": "用户说桶号那列其实叫罐号，已改"}
   ```

8. **跑一次回归测试**：`python tools/回归测试.py` —— 确认新契约没把裁判改坏。

> 已有契约的表型（用户以前确认过）**可以跳过阶段一**，直接从阶段二开始。

## 阶段二：批量转录（闷头干完，不许中途打扰用户）

**这一步的全部原则就是：一口气做完，疑点全部记账，不停下来问人。**

- 照已冻结的契约，**逐张识别剩余图片**；
- 遇到看不清 / 拿不准 → **记进 `uncertain`，继续往下做**，不要停下来问；
- 遇到跟样板不一样的版式 → **照实记、标好 `row_role`，不要自己发明新列**；
- **每识别完一张，就立刻把结果并入 `raw.json` 落盘**——
  绝不攒到最后一次性写。这样断电、关机、人走开都不会丢进度；
- 全部识别完，再跑校验，把问题集中成一份账本：

  ```
  python validate_export.py runs/YYYYMMDD_NNN --init-issues
  ```

> 批量阶段**不要**反复把中间结果拿给用户看。用户的时间只花在两个点上：
> **确认样板**、**复核问题**。

## 阶段三：一次性复核（人只看一次）

1. 生成审核表：

   ```
   python validate_export.py runs/YYYYMMDD_NNN
   ```

2. 把 `task_review.xlsx` 交给用户，请他**只填"问题清单"的员工决定列**——
   没有问题的数据不用逐行确认，看"审核总览"就知道今天录了几张、几个问题。
3. 用户回复"审核完成"后，把审核表内容整理成 `decisions.json`
   （格式见工作区 `AGENTS.md` 第 6 节）。
   **这一步不能省**——Excel 是派生文件、重跑会重写，只有 `decisions.json` 才是权威。
4. **重跑 + 归档**：

   ```
   python validate_export.py runs/YYYYMMDD_NNN --archive
   ```

5. **汇报**：一句话交付——表型、行数、问题数与处理结果、归档结果、文件路径。

## 人工决定的写法

- `字段名=值` → 修正对应字段 / 计量项（图上没读出来的也能补进去）；
- `通过` / `确认无误` / `照录` → 按原样接受，不再阻塞；
- `沿用候选A` / `沿用候选B` → 采用问题清单给的候选值（脚本自动还原，不会把标签当数据）；
- `见备注` → 只看备注、不改数据（该行保持阻塞，直到给出真实值）。

---

## 中断与断点续跑

**任何时候问"做到哪了"，先跑这条命令，然后转述它的输出，不要凭记忆回答：**

```
python validate_export.py runs/YYYYMMDD_NNN --status
```

它会明确告诉你**当前处在哪个阶段**（① 未开始 / ② 立样板 / ③ 批量转录中 / ④ 待统一复核），
还剩哪几张没识别、差几条人工决定、下一步该干什么。

**中断后的固定动作**：跑 `--status` → **只补没做完的部分**（剩 2 张就只做这 2 张）→ 继续往下走。
重复执行同一条命令是安全的：已完成的会跳过，人工决定会保留。

## 出错处理

| 情况 | 处理 |
|------|------|
| 图看不清/倾斜/太暗 | 请用户重拍；原图放 `pending/` |
| 样板被用户否了 | 按意见改契约（或换一张更有代表性的样板图），重新确认 |
| 校验报错（合计超上限等） | 进问题清单，请用户对照原图给正确值，不要自行修改 |
| 脚本报"表名不在已注册契约里" | 说明这批图里混了别的表型，或表名跟样板写得不一样——**不要忽略**，确认后再决定是补契约还是分开处理 |
| 脚本报"结构异常" | `raw.json` 有畸形（如 `fields: null`）。脚本会尽量救回并如实报出，**在汇报里说明** |
| 用户回的数值不合格 | 指出并请其确认，不要替其换算 |
| 归档目标同名 | 脚本自动加 `_2`；绝不覆盖 |
| 任务跑一半中断 | 重跑同一条命令；已落盘内容会复用，人工决定不会丢 |

## 改了裁判脚本或契约之后

```
python tools/回归测试.py
```

40 个"已知答案"的用例，在系统临时目录里跑，**只读真实数据、跑完自动清理**。
全绿才算改对了。契约（`schemas/*.json`）写坏了脚本不会崩，
但会打印「schema 读不了，已跳过」——**看到这行提示要立刻修**。
