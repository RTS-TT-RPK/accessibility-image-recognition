# dsh-table-image 安装说明（手工安装，逐步可核对）

> 目标：把本包挂进 DSH 的 **web profile**，让模型能用上 9 个 `table_image_*` 工具、
> 界面上出现「收图」按钮。
>
> 本插件**只影响 `profiles/web`**，桌面端 profile 不受影响。
>
> ⚠️ 本机（`C:\Users\86173`）**已经装好了**，状态见文末「当前状态」一节。
> 换电脑、或重新装一遍时照下面的步骤走。

## 〇、先记住四条硬规则（每一条都是踩出来的）

> 出处：`DSH测试\02-插件与路由\2026-09-28_profile插件开关_disabled覆盖与bat编码.md`

| # | 规则 | 为什么 |
|---|------|--------|
| 1 | **改之前先备份** `cordis.patch.yml` 与 `package.json`（带时间戳另存一份） | 配置写坏会导致 DSH 起不来，只有备份能救 |
| 2 | **只动顶格（第 1 列）的 `- id:` 条目，绝不碰 insert 块里缩进的那种** | 缩进条目是"挂载声明"，在它后面插 `disabled:` 会造成 YAML 缩进错乱，**DSH 可能起不来** |
| 3 | **找最后一条匹配项，不是第一条**（DSH 只认最后一条覆盖项） | 改第一条的话"配置看起来改了，行为不变"，是最难查的静默失败 |
| 4 | **原子写 + 写后自检**：先写 `.tmp`，自检通过再替换；自检不过就删临时文件、放弃写入、抛错 | 半截写入的 YAML 会让 DSH 直接起不来 |

写后自检至少查三样：
内容非空；**没有 tab 缩进**（`(?m)^\t` 应为空）；原有的挂载声明还都在。

> 另外（与本插件无直接关系，但同一篇文档里的教训）：`.bat` **内容**必须是纯 ASCII
> （cmd 按活动代码页逐字节读 bat，中文会把命令拦腰截断，`chcp 65001` 救不了）；
> `.ps1` 内容可以带中文，但必须存成 **UTF-8 带 BOM**。

## 一、安装三步

### 第 1 步：把本包放进 profile 的 `node_modules`

DSH 的 profile 用 `link:` 依赖挂本地包。做法是给包目录做一个 **junction**
（目录联接，不是复制 —— 以后改本包代码立刻生效）。

```
源目录：C:\Users\86173\Desktop\图像识别长期工程\插件源文件\dsh-table-image
目标：  C:\Users\86173\.dsh\profiles\web\node_modules\dsh-table-image
```

管理员 PowerShell（普通 PowerShell 通常也可以，junction 不需要管理员）：

```powershell
$src = 'C:\Users\86173\Desktop\图像识别长期工程\插件源文件\dsh-table-image'
$dst = 'C:\Users\86173\.dsh\profiles\web\node_modules\dsh-table-image'
New-Item -ItemType Junction -Path $dst -Target $src
```

核对：

```powershell
Get-Item $dst -Force | Select-Object Mode,LinkType,Target
# 期望：Mode=l----  LinkType=Junction  Target=C:\Users\86173\Desktop\图像识别长期工程\插件源文件\dsh-table-image
Test-Path "$dst\index.js"; Test-Path "$dst\client.js"; Test-Path "$dst\package.json"
# 期望：三个都是 True
```

### 第 2 步：profile 的 `package.json` 里加依赖 + 挂组合包

文件：`C:\Users\86173\.dsh\profiles\web\package.json`

```jsonc
{
  "name": "dsh-profile-web",
  "private": true,
  "dependencies": {
    // ……原有的不动……
    "dsh-table-image": "link:C:/Users/86173/Desktop/图像识别长期工程/插件源文件/dsh-table-image"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        // ……原有的不动……
        "dsh-table-image"        // ← 加进组合包列表
      ],
      "patchReload": "live"
    }
  }
}
```

两个要点：

- `dependencies` 里的路径用**正斜杠**（`link:C:/...`）—— 反斜杠在 JSON 里要转义，容易写错；
- `bundles` 里加的是**包名**，不是路径。

### 第 3 步：在 profile 的 `cordis.patch.yml` **末尾**加顶层覆盖项

文件：`C:\Users\86173\.dsh\profiles\web\cordis.patch.yml`

在**文件最末尾**追加（顶格，前面空一行）：

```yaml
- id: table-image
  name: dsh-table-image
  disabled: false
```

四条硬规则在这里怎么落地：

- **顶格**（第 1 列开始）—— 这是"覆盖项"，不是 insert 里的"挂载声明"；
- **放最后** —— DSH 只认最后一条匹配覆盖项；
- 想关掉插件就把它改成 `disabled: true`（左侧栏「插件」页的开关改的也是这一条）；
- 本 profile 是 `patchReload: live` → **存盘即生效**，但**客户端半区的改动要刷新页面（F5）**。

> 本包的 `cordis.patch.yml`（包内那个）里已经有 `- insert: [- id: table-image, ...]`
> 与 `config.workspace: '...'`，那是**组合包**那一层，由第 2 步的 `bundles` 自动叠加，
> 不需要你手写。用户层只需要写上面这三行覆盖项。

## 二、重启并验收

1. **关掉 DSH**（用工作区根目录的 `停止DSH.bat`，或确认 3080 端口没被占）。
2. 启动：工作区根目录的 `启动DSH.bat`（就是 `cd /d F:\deepseek-harness` + `pnpm dsh web`）。
3. **静态验收**（不用开浏览器）：

```powershell
cd /d F:\deepseek-harness
pnpm dsh --profile web --dump-config
```

期望：**退出码 0、零报错、输出里出现 `table-image` 行**。

4. **界面验收**（浏览器 F5 刷新之后）：
   - 输入框工具行上出现一个 **🗂 按钮**；
   - 点一下弹出浅色面板，里面有三个按钮：「处理今天的图」「查一下进度」「收尾归档」；
   - 点「查一下进度」→ 输入框里被填入一段话（**不会自动发送**）；
   - 把一张图片拖到按钮或面板上 → 面板提示"收到 N 张，已放进 inbox/"；
   - 设置页左侧出现一个叫「表格图片转录」的分区（**不是空白行**）。
5. **工具验收**：新开一个会话，问模型「`table_image_status` 这个工具是干什么的、
   现在任务进度怎么样」。它应该能调到工具，并把脚本输出讲给你听。
6. **实机联调**（可选，不开浏览器也能验到底层通不通）：

```powershell
node "C:\Users\86173\.dsh\profiles\web\node_modules\dsh-table-image\dev\tools\real-check.mjs"
```

它会用**真包 + 真 dsh-tools + 真 python** 跑一遍工具与上传端点。
上传那一段在**临时工作区**里跑，不会碰你真实的 `inbox/`。

## 三、卸载 / 回滚

**临时关掉（推荐先这么做）：**

把用户层那条覆盖项改成：

```yaml
- id: table-image
  name: dsh-table-image
  disabled: true
```

存盘（`patchReload: live` 立即生效），刷新页面。想再开就改回 `false`。

**彻底卸掉：**

1. 删掉用户层那三行覆盖项；
2. `package.json` 的 `dependencies` 与 `dsh.profile.bundles` 里各删掉 `dsh-table-image`；
3. 删掉 junction：`Remove-Item 'C:\Users\86173\.dsh\profiles\web\node_modules\dsh-table-image' -Force`
   （删 junction **不会**删源目录，放心）；
4. 重启 DSH。

**出了事回滚：** 用第 1 步备份的 `cordis.patch.yml.bak-<时间戳>` 覆盖回去，重启。

## 四、排障

| 现象 | 先查什么 |
|------|----------|
| DSH 起不来 | 用户层 patch 的缩进写坏了。用备份覆盖回去，重启。检查有没有 tab 缩进、覆盖项是不是顶格 |
| `--dump-config` 里没有 `table-image` 行 | 第 2 步的 `bundles` 没加上，或 junction 没建成功 |
| 插件在「插件」页显示为已启用，但界面没有按钮 | **刷新页面（F5）**。客户端半区的改动必须刷新；还不行就 F12 看 Console 有没有红色报错 |
| 启动报 `Cannot find package '@deepseek-ai/dsh-tools'` | `@deepseek-ai/dsh-tools` 是从 **DSH 给 profile 建的软链场** `~/.dsh/profiles/node_modules/@deepseek-ai/` 里解析的（178 个包，里面有 `dsh-tools` 与 `dsh-host-webserver`）。本机实测：从 profile 目录解析会落到 `F:\deepseek-harness\packages\core\tools\lib\index.js`。若报这个错，检查这个软链场在不在、`F:\deepseek-harness` 是否完整 |
| 工具出现了，但调用时提示"脚本不存在" | 正常。工作区里缺那个 `.py`。本插件按约定的路径调用，脚本一就位就能用 |
| 模型输出里全是乱码 | 本机 `python` 的 stdout 默认是 **GBK**。本插件已经在 spawn 时设 `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1` 兜住了；若仍乱码，检查系统环境变量里有没有把 `PYTHONIOENCODING` 设成别的值 |
| 拖拽区显示"上传通路不可用：…" | 它已经告诉你原因了。多半是 `/table-image/api` 被别的插件占了，或 `webServer` 服务没挂上。看 DSH 启动日志里 `dsh-table-image: 上传端点 …` 那行 |
| 面板跑到屏幕外 / 点了没反应 | 不应该发生（测试台里有 13 组锚点的几何断言）。若真出现，F12 截图发我 |
