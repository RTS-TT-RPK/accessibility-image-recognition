# 通用性测试方案 —— 表格图片转录

> **这份方案测的是「通用性」**：面对**从没见过的表**，这套东西接不接得住。
> **不是**测某几张已知表格（来料分析 / 库存日报）识别得准不准 ——
> 那两份契约只是"已经接住过的例子"，拿它们测只能证明"这两张表 work 过"，证明不了通用。
>
> 将来会有什么表，谁也说不好。所以出题必须**按结构出题，不按行业出题**。

---

## 0. 一句话判据

拿一批互不相关的陌生表型，走完
**建任务 → 立样板 → 注册契约 → 批量转录 → 集中复核 → 归档**，
全程**只许新增数据**（`schemas/*.json`、`runs/`），
`validate_export.py` 与 `tools/` 下的脚本**一行都不许改**。

**改代码才接得住 = 还是特异化的 = 通用性不成立。**

硬证据（不靠嘴说）：

```bat
python 测试夹具/代码快照.py --save     :: 开测前记基线
python 测试夹具/代码快照.py --check    :: 收尾时比对，必须"零改动"
```

---

## 1. 什么算通用，什么不算

| 算通用（应当发生） | 不算通用（一票否决） |
|---|---|
| 新增一份 `schemas/<表型>_v1.json` 就接住新表 | 为了接住某张表去改 `validate_export.py` |
| 单位不是 `%`（元 / 小时 / ℃ / kg / 件）照样能跑 | 代码里写死"百分比"，非百分比就报假问题 |
| 表根本没有"合计"概念 → 关掉合计校验即可 | 对报价单硬套 100% 上限，凭空报"合计超限" |
| 列名由用户拍板，任意列名只要写进契约就能用 | 代码里认表型名、认行业名词 |
| 两级合并表头 / 竖排 / 全英文 / 续表都能记下来 | 某些版式解析崩，或**静默吞掉行** |
| 陌生表型只报一条"表名未注册"提示 | 陌生表型导致脚本抛异常、退出码不是 0/2 |
| 一个任务里混多种表型，各按各的契约走 | 表型之间串契约、张冠李戴 |

## 2. 出题维度（关键：测结构，不测名词）

任何行业都可能长出这些结构，所以**测试维度必须是结构维度**：

| 维度 | 取值范围 | 现有契约覆盖 | 本测试要打到 |
|---|---|---|---|
| **行单位** row_unit | 一个样品 / 一个人一天 / 一个订单项 / 一台设备一次点检 / 一个储位 | 只覆盖"样品""储位" | ✔ |
| **计量项单位** unit | `%` / 元 / 小时 / ℃ / kg / 件 | **只有 `%`** | ✔ **最锋利** |
| **合计上限** sum_max | 100（百分比语义）/ 其它数值 / **无合计概念** | 只有 100 | ✔ |
| 列集合 | 3 列 / 10 列 / 20 列 | 只有 6 列、3 列 | ✔ |
| 表头结构 | 单级 / 两级合并 / 竖排（字段在左）/ 跨页续表 | 只有单级 | ✔ |
| 语言 | 纯中文 / 全英文 / 中英混排 | 只有中文 | ✔ |
| 行身份 | 有主键 / 无主键 / 复合键 | 有主键 | ✔ |
| 特殊行 | 表头 / 小计 / 合计 / 备注 / 承前页 | 覆盖表头、合计、备注 | 部分 |
| 数据形态 | 截图 / 手机拍照 / 扫描件 / 带界面元素 | 只有"照片" | 部分 |
| 质量 | 清晰 / 倾斜 / 暗光 / 手写 / 印章覆盖 | 只有清晰 | 部分 |

## 4. 用例清单

### A 组 · 底座（每轮开测跑一次）

| # | 做什么 | 期望 |
|---|---|---|
| A1 | `python tools/环境自检.py` | 结论"环境齐全"，无 [缺] |
| A2 | `python 测试夹具/代码快照.py --save` | 写下受保护层指纹 |
| A3 | 骨架齐全 | inbox / pending / archive / golden / runs / schemas 都在 |
| A4 | 插件九件套逐个连得上 | start / next / submit / status / check / review / import_review / finalize / register_schema 都返回可读结果；空任务给提示而不是崩 |

### B 组 · 陌生表型接入（**核心** —— 对 G1…G8 每张各跑一遍）

| # | 做什么 | 期望 | 看什么 |
|---|---|---|---|
| B1 | `table_image_start`（只放这张表的一张代表图） | 建出 `runs/<日期>_001/`、`source/names.json`、sha256 真实 | 台账对不对 |
| B2 | `table_image_next` | 给出绝对路径 / 图片编号 / **冻结契约摘要** / 片段模板 | 有没有提示"表名不在已注册契约里" |
| B3 | 看图 → 交片段 | 列名**照图判断**，不许往旧契约上靠 | 分不清的是不是老实进了 `uncertain` |
| B4 | `python tools/生成样板.py runs/<id>` | 出 `样板.xlsx`（5 页签）+ `样板_契约草案.json` | 列名、必填、合计草案合不合理 |
| B5 | 交你确认（**第 5 页签**） | 你写：录法对不对、一行是什么、哪些必填、有没有合计、单位是什么 | 这是唯一的人工关口 |
| B6 | 注册契约 | 写 `schemas/<表型>_v1.json` + `sample.json`，并自动跑回归测试 | **`row_unit` 没回答必须写不进去（硬拦）** |
| B7 | 其余图批量交完 | 一张一张原子落盘 | 中途不打扰人 |
| B8 | `table_image_check` → 看问题清单 | **只有真问题，没有假告警** | ★ 误报数 = 通用性的直接读数 |
| B9 | `review` → 填表 → `import_review` → `finalize` | 出审核表、导入决定、归档原图、出长表 | 归档不改名 / 撞名加序号 |
| B10 | 记分 | 这个表型全程**改代码了吗** | 改了 = 该表型通用性失败 |

### C 组 · 守卫（坏数据必须进不去）

| # | 递进去什么 | 期望 |
|---|---|---|
| C1 | 片段里某行**没有 `row_role`** | 退出码 2 拒绝，**不落盘** |
| C2 | `fields` 里用了**契约外的新列** | 拒绝，并提示"先走注册表型更新契约" |
| C3 | `raw_value` 写成"约九成"这类**解析不出数值**的 | 拒绝（看不清应写进 `uncertain`，不是猜一个数） |
| C4 | `image_id` **不在本任务台账里** | 拒绝并列出可用编号 |
| C5 | 同一张图**重复提交且没加 replace** | 拒绝（防静默覆盖） |

### D 组 · 通用性陷阱（最锋利的一组）

| # | 陷阱 | 为什么锋利 | 期望 |
|---|---|---|---|
| D1 | **钱表**：单位是"元"，合计 12345 元 | 默认契约是 `unit=%`、`sum_max=100`；照默认校验会凭空报"超过上限 100" | 注册契约时把 unit / sum_max 改对，**脚本一行不改** |
| D2 | **无合计表**：报价单 / 名单 | 合计校验对这类表毫无意义 | `measurements.enabled=false` 后问题清单应为空 |
| D3 | **表名漂移**：把"报价单"写成"报价单（新）" | 漂移被静默吞掉 = 数据张冠李戴 | 必须报 `SHEET_UNKNOWN`，不许静默归并 |
| D4 | **一个任务混 3 种表型** | 契约会串吗 | 各按各的契约走，互不污染 |
| D5 | **同行业两套完全不同的列名** | 测列名是否真的只由契约决定 | 只改 schema 就通过 |
| D6 | **温度表**：单位 ℃ | 合计 100℃ 没有物理意义 | 必须能关掉合计校验，而不是硬套 |

### E 组 · 断点 / 复核 / 归档 / 不破坏

| # | 做什么 | 期望 |
|---|---|---|
| E1 | 识别到一半停手，重跑 `--status` | 准确说出停在哪、还剩哪几张；只补没做完的 |

## 6. 判定口径

**通用性通过** = 全部 G 表型都在"零代码改动"下走完全流程，
且**假告警数 = 0**，且 E5 代码快照一致。

**误报率** = 问题清单里"其实没问题"的条数 ÷ 问题总条数 —— 目标 0。
（问题清单里**真问题**不算误报；报得越多越准，说明契约写得越细。）

**一票否决**（任一条即判通用性不成立）：

1. 需要改 `validate_export.py` 或 `tools/*.py` 才能接住某个陌生表型；
2. 对**非百分比单位 / 无合计**的表产出假告警；
3. **表名漂移被静默吞掉**；
4. 该标 `uncertain` 的格子被**硬填了一个数**；
5. 陌生表型导致脚本**异常退出**（退出码不是 0 或 2）。

## 7. 怎么开始

```bat
:: ① 记代码基线（必须第一步，否则"没改代码"没法证明）
python 测试夹具/代码快照.py --save

:: ② 把图扔进 inbox\  —— 任意陌生表，不用分类、不用改名、不用管顺序
::    想要现成的出题图，说一声我按第 3 节清单合成一批

:: ③ 对 AI 说「开始通用性测试」
::    我按 A → B → C → D → E 跑，逐条把结果填进第 5 节记分卡
```

## 8. 两条诚实提醒

1. **出题人不应是答题人。** 合成题我知道答案，测出来的是"结构维度接不接得住"；
   真实世界的表长什么样，只有你的图能回答。**真实图那一轨才算数。**
2. **本方案不改任何脚本。** 它测的对象就是脚本和流程本身；
   它自己唯一的产物是快照工具和这张记分卡。
